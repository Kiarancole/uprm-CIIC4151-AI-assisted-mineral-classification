## Notes and Decisions

Second meeting with the professor, first one that discussed the proposal

- After discussion, the consensus with the professor is that heatmaps will be left as a stretch goal. The main purpose is to work on a web-based tool for image classification. For now we have settled on using Google collab to run these models and conduct preliminary analysis. 

- This tool is to most likely be developed as a web application that calls our API for the functionality.

- As of now we are utilizing the Kaggle dataset we found for training, but the idea in the future is to begin developing and consolidating our own dataset for testing and validation. 

- We must train the models we are to use from scratch. This student-generated allocation of weights will provide a greater contribution justification for the project. Reaching conclusions regarding the decisions made will be part of the development process that justifies the efforts.

- When training these models, the suggestion is to use a larger data set. As we do this, the resulting accuracy is observed.  If this accuracy is not reaching acceptable values, one can scale back the size of the data set and observe the response of the accuracy in relation to it. This exercise done on multiple different models, and observing the differences, will result in a preliminary analysis that will drive our project. 

- In the initial assumptions we must include expectations for accuracy; these can be high. Ending the work with less accuracy than desired is acceptable as the explanations for why could be substantial results. 

    Accuracy is divided into the following ranges:
    - 50%-60%: Acceptable
    - 70%-80%: Good
    - 90%-100%: Excellent

- The professor suggested having a minimum of four metrics that will determine the success and viability of the models. These could be Accuracy, Complexity, Assimilation time, and Similarity
